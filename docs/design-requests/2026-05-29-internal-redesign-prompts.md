# 내부 운영툴 — 신규 디자인 필요 페이지 Claude Design 프롬프트 (2026-05-29)

> **이미 셸/토큰/이식 완료**: 지식(`/kb`)·봇 팀(`/bots`)은 고객 화면(screen-knowledge/screen-team)
> 기반으로 직접 이식. 아래는 **고객 핸드오프에 대응 화면이 없어 신규 디자인이 필요한** 페이지들.
> 결정: `semo decision/internal-tool-brand-migration-2026-05-29`.

## 사용법

각 프롬프트 위에 아래 **공용 프리앰블**을 붙여 Claude Design 에 입력 → 산출물(HTML) 받으면
`semo-design` MCP 로 가져와 Next 로 이식. (구현 시 `components/InternalShell.tsx` 셸 안의 화면으로,
`components/ui/semo.tsx` 의 `PageHeader/Card/Badge/Stat` 프리미티브 재사용.)

```
# 공용: SEMO 운영팀(내부) 화면 — 디자인 시스템
SEMO 내부 운영팀(세미콜론 팀) 화면. 고객 대시보드와 동일한 SEMO v5 시스템.
- 셸: 좌측 사이드바(232px, --semo-bg-soft) + 56px 크림/blur 탑바. 본문은 카드 기반, 좌우 패딩 24px, 최대폭 ~1200.
- 토큰: 크림 배경 #FAF9F4 / 대체 #F4F2EA / 카드 #FFFFFF / 경계 #ECE9DF. 잉크 #1D242B·#3B424B·#6B7280.
  메인 #068FFF, "AI가 한 일" 보라 #7C5CFF, 성공 #10A668·경고 #C97F1A·위험 #D0322C.
- Pretendard. 큰 둥근 카드(12~20), 아주 부드러운 그림자, 넉넉한 여백, tabular-nums, 알약 배지.
- 한국어 UI(팀 내부라 봇 id·commitment 등 용어 노출 OK). 빈 상태 포함. 데스크탑 우선, 라이트 테마.
```

## 1. 로드맵 홈 (`/team`) — 최우선

- **목적**: 팀 첫 화면. 여러 서비스의 마일스톤을 가로 시간축(간트)으로.
- **데이터**: 서비스 도메인 KB `milestone/*` (제목·기간·상태·서비스).

```
[공용 프리앰블]
# 화면: 운영팀 홈 — 로드맵 타임라인
팀 로그인 첫 화면. 여러 서비스의 마일스톤을 가로 시간축 간트로 보여준다.
- 상단: "로드맵" 타이틀 + 상태 필터 세그먼트(전체/진행중/완료) + 오늘 날짜.
- 타임라인 카드: 가로축=월 눈금(5·6·7월…), 세로축=서비스(행). 마일스톤=기간만큼 늘어난
  둥근 막대(서비스별 파스텔). 오늘 세로 가이드선. 막대에 이름+상태 점.
- 막대 클릭 → 우측 슬라이드 패널: 제목·기간·상태 배지·설명·서비스.
- 상단에 요약 Stat 3개(진행중 N · 이번 분기 마감 N · 지연 N) 옵션.
- 빈 상태("마일스톤 없음"). 셸 본문 100% 높이 활용(타임라인은 가로 스크롤 가능).
```

## 2. 액션 아이템 (`/action-items`)

- **데이터**: `action_items` (담당=팀원/봇, 마감, 상태). 뷰: 리스트/칸반/타임라인.

```
[공용 프리앰블]
# 화면: 액션 아이템
팀·봇의 할 일 추적. 리스트/칸반/타임라인 3뷰.
- 헤더: "액션 아이템" + "+ 새 액션". 상단 Stat 행(열림·진행·완료·지연).
- 컨트롤 바: 탭(사람별/프로젝트별) + 뷰 세그먼트(리스트/칸반/타임라인) + 상태 필터(전체/진행/완료).
- 리스트: 행=체크박스(완료 토글)+제목+담당 아바타(팀원 or 봇 이모지)+마감 배지(임박=경고색)
  +대상 서비스 태그+더보기. 그룹 헤더(담당자/서비스)로 묶음.
- 칸반: 상태 컬럼(열림/진행/완료) 카드. 타임라인: 마감일 시간축.
- 생성/수정 모달. 빈 상태.
```

## 3. 회의 (`/meetings`)

- **데이터**: `meetings` (업로드→녹취→회의록 생성 상태 흐름).

```
[공용 프리앰블]
# 화면: 회의
회의 녹음 업로드 → 녹취 → 회의록 자동 생성 흐름 관리.
- 헤더: "회의" + "+ 새 회의".
- 회의 카드/행: 제목 + 날짜 + 상태 배지(대기=중립·업로드=경고·녹취중=블루펄스·완료=성공·생성중=보라펄스·실패=위험).
  진행 중은 펄스/진행률. 클릭 → 상세.
- 상단 옵션: 이번 주 회의 N · 회의록 생성 완료 N Stat.
- "새 회의" 는 녹음 업로드/드래그drop 카드. 빈 상태.
```

## 4. 목표 정렬 (`/goals`)

- **데이터**: `/api/goals` — 서비스 도메인별 마일스톤·결정·액션·프로젝트 집계.

```
[공용 프리앰블]
# 화면: 목표 정렬
서비스별로 목표(마일스톤·결정·액션·프로젝트)를 모아 정렬.
- 헤더: "목표 정렬" + 총계.
- 서비스 도메인 카드(아코디언): 접힘=도메인명+설명+4개 카운트 칩(마일스톤·결정·액션·프로젝트).
  펼침=4개 섹션 리스트(아이콘+라벨+항목 제목+날짜 배지).
- 데스크탑 2열 그리드. 빈 상태.
```

## 5. 서비스 (`/projects`)

- **데이터**: 서비스 KB `pipeline/config` (lifecycle/type/phase) + 비용.

```
[공용 프리앰블]
# 화면: 서비스 (프로젝트)
세미콜론이 만드는/운영하는 서비스 진행 현황.
- 헤더: "서비스" + "+ 새 서비스". 1차 탭(일반/인큐베이터/플랫폼) + lifecycle 필터(전체/구축/운영/종료).
- 프로젝트 카드: 서비스명 + lifecycle 배지(구축=블루/운영=성공/종료=회색) + 타입 배지(외부=주황/플랫폼=보라)
  + 페이즈 진행 "리더보드 트랙"(트랙 위 러너로 서브페이즈 진행률) + 누적 비용$·토큰(작게).
- 카드 클릭 → 상세. 데스크탑 2~3열. 빈 상태.
```

## 6. 조직도 (`/org`)

- **데이터**: `/api/org` (봇 노드 + 위임 엣지).

```
[공용 프리앰블]
# 화면: 조직도
봇 팀 위임 구조를 노드-엣지 그래프로.
- 헤더: "조직도" + "N개 봇, M개 위임 흐름".
- 방향 그래프(큰 캔버스 카드): 노드=봇(이모지 아바타+이름+역할 카드), 엣지=위임 방향(곡선 화살표).
  오케스트레이터(Semi/Colony) 중심/상단, 전문 봇이 가지. 노드 hover 시 연결 엣지 강조. 줌/팬.
```

## 7. 위임 현황 (`/orchestrator-flow`)

- **데이터**: `bot_commitments` (runtime_source='hermes-orchestrator'), 신규 사용자 KB.

```
[공용 프리앰블]
# 화면: 위임 현황 (Orchestrator Flow)
Semi 가 전문 봇에 위임한 작업의 "위임→처리→완료" 실시간 현황.
- 헤더: "위임 현황" + 부제. 상단 라이브 배너(연결 상태 + 방금 바뀐 항목 하이라이트).
- "최근 위임 작업" 리스트: 행=상태 배지(⏳진행/✅완료/⚠️실패) + 라우팅 경로(@Semi → @workclaw, 아바타)
  + 작업 제목 + 발신 사용자 + 시각. 진행 중 펄스.
- 하단 "최근 신규 사용자(7일)": 닉네임+도메인+역할/AI친숙도 칩 카드.
- 빈 상태.
```

## 가벼운 페이지 (별도 디자인 불요 — 공용 프리미티브로 정렬)

`/board`(자료실) · `/person`(팀원) · `/cost`(비용) · `/agents`(에이전트) · `/tasks`(런) · `/admin/*`
→ `PageHeader` + `Card`/`Stat`/`Badge` + 셸 토큰으로 정렬(필요 시 위 패턴 차용).

## 직접 이식 (Claude Design 불요)

- **지식 `/kb`** ← 고객 `screen-knowledge`(도메인 카드 그리드 + 지식 그래프) 기반. 이미 DomainCard·탭 사용.
- **봇 팀 `/bots`** ← 고객 `screen-team`(AgentCard 카드 그리드: 아바타+상태점+요약칩+스킬 배지) 기반.
