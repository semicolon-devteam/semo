# 내부 운영툴 → SEMO v5 디자인 이식 — Claude Design 프롬프트 모음 (2026-05-29)

> deep-interview 로 범위/기준 확정 후 산출. 결정: `semo decision/internal-tool-brand-migration-2026-05-29`.
> 디자인 기준 = **고객 대시보드 v5 사이드바 셸**(핸드오프 `screen-provider.jsx` 패턴). 데이터/로직 불변, 표현만 이식.

## 사용법

각 페이지 프롬프트를 Claude Design 에 넣을 때 **아래 "공용 시스템 프리앰블"을 먼저 붙이고**, 그 다음 해당 페이지 블록을 이어 붙인다. (또는 기존 핸드오프 프로젝트에 이어서 새 화면으로 생성.)

---

## 공용 시스템 프리앰블 (모든 페이지 공통 — 매 프롬프트 상단에 첨부)

```
# SEMO 운영팀(내부) 대시보드 — 공통 디자인 시스템

이건 SEMO 의 **내부 운영팀(세미콜론 팀)** 화면이다. 고객 대시보드(SEMO Dashboard v5)와
**동일한 디자인 시스템**을 쓴다 — 같은 셸, 같은 컴포넌트, 같은 토큰. (dogfooding)

## 셸 (모든 화면 공통)
- 좌측 **사이드바**(232px, 배경 --semo-bg-soft): 상단 SEMO 로고(; 마크) → 워크스페이스
  스위처("세미콜론 팀 · 운영팀") → 내비 항목. 내비: 홈(로드맵)·봇 팀·지식·액션·목표·회의·
  서비스·조직도·위임 현황. 하단에 도움말·설정.
- 상단 **탑바**(56px): 페이지 타이틀 + 검색(⌘K) + 알림 벨 + 아바타.
- 본문은 카드 기반. 최대폭 넉넉히, 좌우 패딩 24px.

## 토큰 / 룩앤필
- 배경 크림 #FAF9F4, 대체 표면 #F4F2EA, 카드 흰색 #FFFFFF, 경계선 #ECE9DF.
- 본문 잉크 #1D242B / #3B424B / #6B7280. 메인 컬러(액션·강조·링크) 블루 #068FFF.
  "AI 가 한 일" 강조는 보라 #7C5CFF. 성공 #10A668 / 경고 #C97F1A / 위험 #D0322C.
- 폰트 Pretendard. 큰 둥근 카드(radius 12~20), 아주 부드러운 그림자, 넉넉한 여백.
- 숫자는 tabular-nums. 상태는 알약형 배지(둥근 pill).

## 컴포넌트 (재사용)
- Card / Section(eyebrow+title+action) / Badge(neutral·primary·success·warning·danger)
- Stat(label+큰 숫자+델타 배지+미니 차트) / Button(primary·secondary·ghost)
- 좌측 아이콘은 lucide 계열 라인 아이콘(stroke 1.6).

## 규칙
- 한국어 UI. 기술 용어는 팀 내부 화면이라 OK(봇 id, commitment 등 그대로).
- 데이터 없을 때의 빈 상태(empty state)도 디자인할 것.
- 반응형은 데스크탑 우선(팀 업무용). 모바일은 사이드바 접힘 + 1열.
- 라이트 테마 기준.
```

## 1. 홈 — 로드맵 타임라인 (`/team`)

- **목적**: 팀의 첫 화면. 서비스별 마일스톤을 시간축(간트)으로 한눈에.
- **콘텐츠/섹션**: 상단 헤더(타이틀 + 상태 필터: 전체/진행중/완료) → 월(month) 눈금 가로축 → 서비스(행)별 마일스톤 바(색상=서비스, 위치=기간) → 마일스톤 클릭 시 상세 모달. 빈 상태("마일스톤 없음").
- **데이터**: 서비스 도메인 KB `milestone/*`.
- **액션**: 상태 필터, 마일스톤 클릭→상세.

```
[공용 시스템 프리앰블 첨부]

# 화면: 운영팀 홈 — 로드맵 타임라인

팀이 로그인하면 처음 보는 화면. 여러 서비스의 마일스톤을 가로 시간축(간트 차트)으로 보여준다.

- 상단: "로드맵" 타이틀 + 우측에 상태 필터 세그먼트(전체 / 진행중 / 완료).
- 타임라인: 가로축은 월(예: 5월·6월·7월…) 눈금. 세로축은 서비스(행). 각 마일스톤은
  기간만큼 가로로 늘어난 둥근 막대(서비스별 파스텔 색). 막대 안/옆에 마일스톤 이름.
  오늘 날짜 세로 가이드 라인.
- 막대 클릭 → 우측 슬라이드 패널 또는 모달: 마일스톤 제목·기간·상태·설명·관련 서비스.
- 빈 상태: 가운데 일러스트 + "아직 마일스톤이 없어요" + 추가 안내.
- 위 공통 셸(사이드바: '홈' 활성) 안에 배치.
```

## 2. 봇 팀 현황 (`/bots`)

- **목적**: 모든 봇의 상태·활동 모니터링.
- **콘텐츠/섹션**: 시스템 헬스 배너(상단 경보) → 런타임 소스 차트(최근 7일, 봇별 처리량) → 봇 카드 그리드(이모지·이름·역할·온/오프라인·세션 수·마지막 활동·워크스페이스 경로). 상세는 `/bots/[id]`.
- **데이터**: `semo.bot_status`, KB `bot-config/identity`, runtime-source 집계.
- **액션**: 봇 카드 클릭→상세.

```
[공용 시스템 프리앰블 첨부]

# 화면: 봇 팀 현황

세미콜론 팀의 모든 AI 봇 상태를 모니터링하는 화면.

- 상단: "봇 팀 현황" 타이틀 + 부제 "모든 봇의 활동과 상태를 모니터링합니다".
- 시스템 헬스 배너: 이상 있으면 경고색 띠(정상이면 옅은 성공 띠 또는 숨김).
- 런타임 소스 차트: 최근 7일 봇별 처리량을 보여주는 가로 막대/스택 차트 카드.
- 봇 카드 그리드(3열): 각 카드 = 봇 이모지 아바타 + 이름 + 역할 + 온라인/오프라인
  상태 점(배지) + 세션 수 + 마지막 활동 시각 + 워크스페이스 경로(작게, mono).
  온라인은 성공색 점, 오프라인은 회색.
- 빈/에러 상태("등록된 봇이 없습니다" / "DB 연결 실패") 포함.
```

## 3. 지식 — KB (`/kb`) · `/ontology` 통합

- **목적**: 팀 지식베이스(KB) 탐색·검색·CRUD + 온톨로지(도메인 스키마) 뷰.
- **콘텐츠/섹션**: 헤더(타이틀 + "새 항목" CTA) → 필터 바(검색 입력+버튼, 봇 셀렉트, 태그 셀렉트) → 탭(도메인 / 항목 / 온톨로지) → (도메인) 도메인 카드 그리드 / (항목) 항목 테이블[도메인·키·내용·작성자·유사도] / (온톨로지) Global·서비스별 도메인 카드 → 카드/행 클릭 시 2-레이어 모달(카테고리→항목 상세, 수정/삭제) → 새 항목/수정 폼 모달.
- **데이터**: `/api/kb` (도메인/항목/검색/온톨로지).
- **병합**: 기존 `/ontology` 단독 페이지는 이 화면의 "온톨로지" 탭으로 흡수(→ `/kb?tab=ontology` 리다이렉트).

```
[공용 시스템 프리앰블 첨부]

# 화면: 지식 (KB) — 온톨로지 탭 포함

팀 지식베이스를 탐색·검색·관리하는 화면. (기존 별도 '온톨로지' 페이지를 이 화면의 탭으로 흡수)

- 헤더: "지식" 타이틀 + "KB 항목 관리 — N개 항목" 부제 + 우측 "+ 새 항목" 프라이머리 버튼.
- 필터 바(카드): 검색 입력 + 검색 버튼 / 봇 드롭다운 / 태그 드롭다운.
- 탭: [도메인] [항목] [온톨로지].
  - 도메인 탭: 도메인 카드 그리드(아이콘 + 도메인명 + 항목 수). 검색 시엔 도메인별 그룹 + 항목 리스트(유사도 % 배지).
  - 항목 탭: 테이블(도메인 배지 / 키 / 내용 미리보기 / 작성자 / 검색 시 유사도). 행 hover 강조.
  - 온톨로지 탭: "Global" 섹션 + "서비스: {name}" 섹션별 도메인 카드 그리드.
- 도메인/항목 클릭 → 2단 레이어 모달: (1단) 도메인의 항목 리스트 → (2단) 항목 상세
  (내용 mono 블록 + 태그 + 수정일 + 수정/삭제 액션). 뒤로가기 지원.
- 새 항목/수정 폼 모달: 제목·내용(textarea)·봇·카테고리(도메인) 입력.
- 유사도 배지 색: ≥70 성공 / ≥50 경고 / 그외 중립.
```

## 4. 액션 아이템 (`/action-items`)

- **목적**: 팀/봇 액션 아이템(할 일) 추적.
- **콘텐츠/섹션**: 헤더 + stats(열림/완료 등) + 뷰 전환(리스트/칸반/타임라인) + 상태 필터 + 탭 + 항목 행(담당자=팀원/봇, 마감, 상태 토글) + 생성/수정 폼 모달.
- **데이터**: `action_items` (semo action-items adapter), 팀원/서비스 도메인.
- **액션**: 생성/수정/삭제, 상태 토글, 뷰 전환, 담당자 필터.

```
[공용 시스템 프리앰블 첨부]

# 화면: 액션 아이템

팀과 봇의 할 일(액션 아이템)을 추적·관리하는 화면.

- 헤더: "액션 아이템" + 우측 "+ 새 액션" 버튼.
- 상단 stats 행: 작은 Stat 카드들(열림 N · 진행 N · 완료 N · 지연 N).
- 컨트롤 바: 뷰 전환 세그먼트([리스트] [칸반] [타임라인]) + 상태 필터 + 담당자 필터.
- 리스트 뷰: 행마다 체크박스(완료 토글) + 제목 + 담당자 아바타(팀원 or 봇) + 마감일 배지
  (임박=경고색) + 대상 서비스 태그 + 더보기(수정/삭제).
- 칸반 뷰: 상태별 컬럼(열림/진행/완료)에 카드.
- 타임라인 뷰: 마감일 기준 시간축 배치.
- 생성/수정 폼 모달: 설명·담당자·마감일·대상 서비스.
- 빈 상태 포함.
```

## 5. 목표 정렬 (`/goals`)

- **목적**: 서비스별 목표 정렬 — 마일스톤·결정·액션·프로젝트를 한 도메인 카드로 묶어 봄.
- **콘텐츠/섹션**: 헤더 + 총계 + 서비스 도메인별 확장(accordion) 카드(설명 + 마일스톤/결정/액션아이템/프로젝트 4개 그룹).
- **데이터**: `/api/goals` (서비스 도메인 KB 집계).
- **액션**: 카드 펼치기/접기.

```
[공용 시스템 프리앰블 첨부]

# 화면: 목표 정렬

서비스별로 목표(마일스톤·결정·액션·프로젝트)를 한데 모아 정렬해 보여주는 화면.

- 헤더: "목표 정렬" + 부제(총 N개 항목 across M개 서비스).
- 서비스 도메인별 카드(아코디언): 접힌 상태엔 도메인명 + 설명 + 4개 카운트 칩
  (마일스톤 N · 결정 N · 액션 N · 프로젝트 N). 펼치면 4개 섹션으로 각 항목 리스트.
- 각 섹션은 아이콘 + 라벨 + 항목들(제목 + 짧은 메타). 결정/마일스톤은 날짜 배지.
- 빈 상태 포함. 데스크탑 2열 그리드, 모바일 1열.
```

## 6. 회의 (`/meetings`)

- **목적**: 회의 녹음 업로드 → 녹취 → 회의록 자동 생성 추적.
- **콘텐츠/섹션**: 헤더(+ "새 회의") + 회의 목록(제목·날짜·상태 배지: 대기/업로드/녹취중/완료/생성중/실패) + 상세는 `/meetings/[id]`, 생성은 `/meetings/new`.
- **데이터**: `meetings` 테이블.
- **액션**: 새 회의(업로드/녹음), 회의 클릭→상세, 상태 폴링.

```
[공용 시스템 프리앰블 첨부]

# 화면: 회의

회의 녹음을 올리면 녹취 → 회의록 자동 생성까지 처리되는 흐름을 관리하는 화면.

- 헤더: "회의" + 우측 "+ 새 회의" 버튼.
- 회의 목록(카드 또는 행): 제목 + 날짜(YY-MM-DD) + 상태 배지.
  상태 배지 색/문구: 대기(중립) · 업로드 중(경고) · 녹취 중(블루, 펄스) · 녹취 완료(성공)
  · 생성 중(보라, 펄스) · 완료(성공) · 실패(위험).
- 진행 중 항목은 진행 표시(스피너/펄스). 행 클릭 → 상세.
- 빈 상태("아직 회의가 없어요" + 새 회의 안내) 포함.

## 7. 서비스 (`/projects`)

- **목적**: 인큐베이팅/플랫폼 서비스 프로젝트 진행 현황.
- **콘텐츠/섹션**: 헤더 + 1차 뷰 전환(일반/인큐베이터/플랫폼) + lifecycle 필터 탭(전체/구축/운영/종료) + 프로젝트 카드(상태·lifecycle 배지·서비스 타입 배지·페이즈 진행 LeaderboardTrack·비용). 상세 `/projects/[id]`.
- **데이터**: 서비스 KB `pipeline/config`, 비용 집계, 페이즈 진행.
- **액션**: 뷰/필터 전환, 프로젝트 클릭→상세, 새 프로젝트.

```
[공용 시스템 프리앰블 첨부]

# 화면: 서비스 (프로젝트)

세미콜론이 만드는/운영하는 서비스 프로젝트들의 진행 현황 화면.

- 헤더: "서비스" + 우측 "+ 새 서비스".
- 1차 뷰 탭: [일반] [인큐베이터] [플랫폼] (권한에 따라 노출).
- 보조 필터: lifecycle 세그먼트(전체 / 구축 중 / 운영 중 / 종료).
- 프로젝트 카드: 서비스명 + lifecycle 배지(구축=블루 / 운영=성공 / 종료=회색)
  + 서비스 타입 배지(외부=주황 / 플랫폼=보라) + 상태(active/paused/completed)

  + 누적 비용($)·토큰 수(작게).
- 카드 클릭 → 상세. 빈 상태 포함. 데스크탑 2~3열.

## 9. 위임 현황 — Orchestrator Flow (`/orchestrator-flow`)

- **목적**: Semi 가 전문 봇에게 위임한 작업의 진행(위임→처리→완료)을 실시간으로.
- **콘텐츠/섹션**: 헤더 + 라이브 배너(SSE) + 최근 위임 작업 리스트(routed_from→bot_id, 상태 active⏳/done✅/failed⚠️, 제목, 발신자, 시각) + 최근 신규 사용자(7일).
- **데이터**: `semo.bot_commitments` (runtime_source='hermes-orchestrator'), KB `team-*`.
- **액션**: 실시간 갱신(SSE/폴링).

```
[공용 시스템 프리앰블 첨부]

# 화면: 위임 현황 (Orchestrator Flow)

Semi(오케스트레이터)가 전문 에이전트에게 위임한 작업이 "위임 → 처리 → 완료"로
흐르는 현황을 실시간으로 보여주는 화면.

- 헤더: "위임 현황" + 부제(Semi 가 위임한 작업의 진행).
- 상단 라이브 배너: 실시간 연결 상태 + 방금 바뀐 항목 하이라이트.
- "최근 위임 작업" 리스트: 각 행 = 상태 배지(⏳ active 진행 / ✅ done 완료 / ⚠️ failed 실패)
  + `@Semi → @workclaw` 처럼 라우팅 경로(보낸 봇 → 받은 봇, 아바타) + 작업 제목
  + 발신 사용자 + 시각. 진행 중은 펄스.
- 하단 "최근 신규 사용자(7일)": 닉네임 + 도메인 + 역할/AI 친숙도 칩 카드.
- 빈 상태 포함.
```
