## 1. 목표 / 범위 / 비목표

**목표**: 주얼리 소상공인이 **월 구독(프로모 10~20만, 목표 30만)** 으로 설치받아 즉시 쓰는, "콘텐츠 자동생성 + 인증 작업 1개(손) + 컨시어지 이미지" 1차 상품 출시.

**범위(1차)**: **가게별 소형 온톨로지(Colony 자동 추출·성장 = 핵심 차별점/지식 해자)** + 콘텐츠 5모듈 + 손 2-bet(둘 중 하나만 성공해도 1차 성공) + 컨시어지 이미지 + 중앙 대시보드 + 결제 + 온보딩.

> **핵심 차별점**: Hermes/OpenClaw는 범용 엔진(가게 지식 0). 우리 해자 = 「가게별 온톨로지(지식)」 × 「제품화된 손(행동+승인)」 × 「콘텐츠+컨시어지+설치대행」. 온톨로지(E0)가 전 모듈 그라운딩의 토대.
> **비목표(2차 이후)**: 카톡 손님 자동응대, 주문/예약/재고/매출 자료관리 모듈, CSV 인입, 관리형 클라우드 작업공간(고객 PC 대체), 자체 오픈웨이트 모델.

## 2. 아키텍처 (2층)

```
[고객 PC — "손"]                         [중앙 — "두뇌"]
 Hermes 에이전트                           kb-gateway(백엔드, 이미 작동·외부공개 필요)
 + Playwright 퍼시스턴트 세션   ──Bearer──▶  → appdb / KB (고객사별 격리, 검증완료)
 + 고객 본인 로그인 세션                     중앙 대시보드(로그인) — 자료·AI직원·결제·산출물
 작업 폴더(파일 생성)                        중앙 요청 큐(inbox/outbox) — PC 오프라인 대비
 컨시어지: 이미지요청 → 중앙DB+슬랙 → 우리팀 생성 → 산출물 중앙저장 → 대시보드 전달
```

- **재사용(이미 있음)**: kb-gateway(멀티테넌트·토큰발급), customer-runtime(설치→투영), Hermes `computer_use`(macOS) + Playwright(웹·크로스플랫폼), 콘텐츠 생성 부품(blog/portfolio/illustration), agent_personas/톤.
- **신규**: 게이트웨이 외부공개+TLS, 콘텐츠 모듈 스킬화, 손 2종, 컨시어지 파이프라인, 산출물 중앙저장, 결제, 온보딩 마법사.
- **데이터 규칙**: 게시용 산출물=중앙(대시보드 다운로드) / 민감=로컬·고객클라우드 / 메타 항상 DB.
- **크리덴셜**: 에이전트 전용 브라우저 프로필(세션 영속, PoC 입증) + OS 키체인. 평문 .env 지양, 프로필 디스크 암호화. 우리 서버엔 고객 인증정보 미보관.

## 3. Epic / 티켓 분해 (난이도 S/M/L · 완료기준)

### E0. 가게별 소형 온톨로지 — Colony 자동 추출·성장 (난이도 L, 핵심 차별점)

> 전 모듈의 그라운딩 토대. substrate 재사용: `128_entity_relations`(relation_types 통제 enum·status·confidence·tenant_id·source_ref), `129` tenant KB, `colony-digest.ts`(채널 fetch→hermes 추출→KB upsert), `channel_domain_map`, 대시보드 `/my/knowledge`.
> **검증(2026-06-09)**: 주얼리 어휘 27종 라이브 적용(`130_jewelry_relation_types.sql`). 1사이클 PoC PASS — 추출(시뮬)→proposed→임계0.85 자동승인4/보류2→`v_entity_relations_live`→그라운딩 조립(`docs/reports/poc/e0-ontology-cycle-poc.mjs`). 잔여=아래 T0.2~T0.5(LLM 추출·넛지UI·그라운딩 주입·라이브 그래프).

- **T0.1 온보딩 시드 → 온톨로지 초기화**(M) — 온보딩 입력(가게/상품/정책/톤)을 entity_relations(tenant-local)로 시드. 완료: 시드 관계가 /my/knowledge에 표시·모듈 그라운딩에 사용.
- **T0.2 Colony 추출 루프 재배선(고객 테넌트용)**(L) — `semo-colony` hermes가 테넌트 소스(온보딩·사장님↔에이전트 대화·손-행동 관찰·생성물)에서 관계 추출 → `entity_relations(status='proposed', confidence, source_ref, tenant_id)`. 출처=테넌트 자기데이터만(카톡=2차). 완료: 실데이터에서 proposed 관계 N건 생성·출처기록.
- **T0.3 confidence 임계 하이브리드 승인**(M) — 고신뢰(≥~0.85)=auto-approve(라이브) / 중간·상충=대시보드 1-탭 넛지("이 가게 ○○ 맞나요?") / 저신뢰·구조변경=컨시어지. 완료: 3분기 동작 + approved만 그라운딩 노출.
- **T0.4 그라운딩 연결**(M) — approved 온톨로지를 E1/E2 생성 컨텍스트에 주입(kb-gateway 경유). 완료: 상세페이지·응대 생성물이 가게 특정 사실 반영(일반 ChatGPT와 구별되는 산출).
- **T0.5 /my/knowledge 라이브 그래프 + 넛지 UI**(M) — mock→실데이터. 완료: 라이브 그래프 + 1-탭 넛지 1사이클.
- **의존성**: 129 tenant KB, kb-gateway, Colony hermes. **튜닝 미결**: 임계값·넛지빈도 상한·주얼리 relation_type enum 세트.

### E1. 콘텐츠 5모듈 (난이도 M, 1차 핵심)

> **그라운딩 규칙(전 모듈 공통, 2026-06-09 PoC 확정)**: 생성은 항상 **KB(가게 프로필·속성·정책) + 온톨로지(승인 관계)** 둘 다에 그라운딩. 관계 단독 금지(소재·관리법·주문제작 등 핵심은 속성=KB). **지식 밖은 단정 금지 → "확인 후 안내"**(거짓 부정 방지). 근거: `docs/reports/poc/jumuni-agent-e2e-result.md`(v1 관계만→거짓응답, v2 KB+온톨로지→정확). **E1 5모듈 전부 그라운딩 작동 검증됨**(`e1-content-modules-result.md`: 상세페이지·SNS·포스터·브랜드 + 응대). ⚠️ **프로모 가드(T1.4/E8)**: 홍보·이벤트 문구는 할인율·기간 등 _프로모 사실을 사장님 입력에서만_ 사용(가격·할인 발명 금지) — PoC서 포스터가 '할인 이벤트' 환각함.

- **T1.1 상품/브랜드 입력폼 + 테넌트 KB 저장**(M) — 대시보드 입력 → `kb-gateway` upsert(테넌트 도메인). 완료: 입력값이 KB에 저장·재조회.
- **T1.2 상세페이지 글 스킬**(M) — 상품 KB → 소개·구매포인트·소재·관리·배송·교환환불·CTA 생성. 완료: 샘플 상품 1건 전체 섹션 생성·대시보드 표시.
- **T1.3 SNS·홍보 콘텐츠 스킬**(M) — 인스타 글·카드뉴스 구성안·블로그 초안·해시태그·지역키워드·주간토픽. 완료: 1주치 콘텐츠 산출.
- **T1.4 포스터·카드뉴스 문구 스킬**(S) — 제목·짧은 홍보·이벤트·3~5장 구성안(비주얼은 컨시어지). 완료: 카드 3~5장 outline.
- **T1.5 고객 응대 문구 스킬**(M) — 문의유형분류(가격/재고/배송/주문제작/예약/교환환불/컴플레인) + 톤 프리셋(친근/정중/고급) → 생성, **사장님 검토·발송**. 완료: 7유형 × 3톤 샘플.
- **T1.6 브랜드 기초 세팅 마법사**(M, E7과 연계) — 소개·철학·타깃·키컬러·톤·IG프로필·메인문구·FAQ·카테고리. 완료: 온보딩서 1회 입력 → 타 모듈이 참조.
- **의존성**: kb-gateway 테넌트 쓰기(있음), 페르소나/톤(있음). **공통 가드레일(E8)**: 건기식 효능표현 필터.

### E2. 손-안전베팅: 시장가 조사 (난이도 S~M) — **PoC 결과 피벗 반영**

- **T2.1** 퍼시스턴트 세션 + 스크랩+집계 파이프라인(✅ PoC 입증) 제품화.
- **T2.2 (중요)** 데이터 소스: **공개 네이버쇼핑 스크랩은 안티봇/CAPTCHA로 불가(PoC 확인)** → **공식 API 우선**(네이버 검색/쇼핑 API 등) 또는 _고객 인증 세션_ 경유로 피벗. 완료: 실제 "유사 상품 평균/가격대" 리포트(실데이터)가 대시보드에 표시.

### E3. 손-하이베팅: 스마트스토어 자동등록 (난이도 L) — 테스트 판매자계정 의존

- **T3.2** 브라우저 경로: 1회 headed 수동 로그인(2FA) → 동일 userDataDir에 세션 영속(✅ 입증) → 무인 재사용. 상품 1건 등록 직전 **승인 게이트** + **감사로그**.
- **완료**: 테스트 판매자계정에 상품 1건 자동 등록(상세페이지 글 T1.2 연동) + 승인/로그 동작.

## 4. 우선순위 / 마일스톤

1. **M0 (선결)**: E5.1 게이트웨이 외부공개+TLS, E8 가드레일 골격.
2. **M1 (손 검증, 최우선)**: **E2(안전베팅, API 피벗) 먼저** → 가능하면 E3(하이베팅, 테스트계정). _둘 중 하나만 성공해도 1차 게이트 통과._
3. **M2 (온톨로지+콘텐츠)**: **E0 온톨로지(시드 T0.1→추출 T0.2→승인 T0.3→그라운딩 T0.4→그래프 T0.5)** + E1 5모듈 + E5.2 산출물저장 + E5.4 대시보드 실데이터. (E0가 E1 그라운딩 토대 → 병행/선행)
4. **M3 (상품화)**: E4 컨시어지, E6 결제, E7 온보딩.
5. **M4 (확장)**: 바이크정비·건기식 변형(업종 템플릿), 2차(자료관리·카톡) 착수.

- 1차 목표 4~6주(콘텐츠 중심), 손·결제·온보딩 포함 시 +α.
