한 줄 결론 — 제품은 2층 구조(두뇌=중앙 / 손=고객PC)이고, 진짜 경쟁력(해자) = 「가게별 지식(온톨로지)」 × 「제품화된 손」 × 「콘텐츠+컨시어지+설치대행」입니다. 범용 AI 에이전트(예: 챗봇 엔진)와의 결정적 차이는 — 그 가게를 ‘아는’ AI(상품·정책·말투를 구조화해 *쓸수록 똑똑해지는* 지식)와, 그 지식으로 실제 일을 ‘하는’ 손입니다. 둘 다 1차에 포함. 1차 = 가게별 온톨로지(자동성장) + 콘텐츠 5 + 손 2-bet + 컨시어지 이미지, 월 구독 10~20만(목표 30만), 주얼리 우선·3업종 동시. 4~6주 목표.

1차 검토에서 확정된 방향

2026-06-09

📍 데이터 · 두뇌 = 중앙 (+ 가게별 지식)

  • 모든 고객 자료는 중앙 저장소에 — 우리가 만들던 ‘백엔드 서버’가 그 통로(이미 작동, 고객사별 안전 분리)
  • ★ 가게별 지식(온톨로지) — AI가 그 가게의 상품·정책·말투를 구조화해 보관하고, 쓸수록 자동으로 키움(전담 에이전트 Colony). 모든 기능의 ‘그 가게를 아는’ 토대.
  • 관리화면(대시보드)도 중앙 1개 — 로그인해서 자료·AI직원·지식그래프·결제 확인

💻 에이전트 실행 = 당분간 고객 PC

  • AI가 파일을 만들고 다루려면 ‘작업 공간(폴더)’이 필요 → 중앙 실행환경 완성 전까지 고객 PC가 그 역할
  • 임시 전략임을 명시 — 고객 늘면 ‘클라우드 작업공간’으로 전환
  • 단, 키·요청·결과는 중앙 경유로 설계(아래 ‘보완 4가지’)

💬 1차 채널 = 대시보드(카톡 X)

  • 1차 5기능은 사장님이 대시보드에서 받아 직접 활용 → 카톡 연동 불필요
  • 고객 응대 문구도 AI 생성 → 사장님 검토·수정·발송(반자동)
  • 손님 자동응대(카톡)는 2차로 분리

🎨 1차 이미지 = 컨시어지(사람 손)

  • 고객 요청 → 우리 DB 적재 + 슬랙 알림 → 우리 팀이 직접 생성해 전달
  • 이미지 파이프라인 구축 0으로 빠르게 시작(똑똑한 우회)
  • 리스크 인지: 사람 손 = 확장 한계 + 상업용 라이선스 확인 필요

1차 구조 한 장 요약

이미 되는 것 + 남은 것
핵심: 이미 되는 것 = 중앙 저장소·백엔드(게이트웨이)·고객사별 분리·AI의 정보 읽기/쓰기. 남은 것 = 백엔드 외부 공개(보안), 대시보드 실데이터·결제, 콘텐츠 5기능, 모델 계정 정책.

PC 설치, 이렇게 보완해야 합니다 (검토 의견)

1. 산출물은 중앙으로도 보내기

AI가 만든 글·포스터가 고객 PC 폴더에만 있으면 중앙 대시보드에서 못 보여줌. 결과물을 중앙에도 올려 대시보드에서 보고·다운로드.

2. 우리 키는 PC에 두지 않기

모델 키를 고객 PC에 깔면 모든 PC에 키를 뿌리는 셈(유출 위험). 모델·이미지·KB 호출은 전부 중앙 경유(키는 서버에만). → 모델 권한 리스크도 동시 해소.

3. ‘항상 켜짐’ 회피 = 중앙 큐

대시보드에서 작업 걸었는데 PC가 꺼져 있으면 실패. 중앙에 요청 큐를 두고 PC가 켜질 때 받아 처리(이미 우리 구조에 있음).

4. 결국은 ‘클라우드 작업공간’

“클라우드 샌드박스를 못 만든다”는 아직 안 만든 것에 가까움. 관리형 서비스(E2B·Modal·Fly 등)로 고객별 격리 작업공간 제공이 정공법 → v2에서 PC 의존 제거.

꼭 짚을 리스크

⚠ 모델 계정 정책

ChatGPT 다계정 동적 구독은 약관 위반·밴 리스크. 정식 API/고객 계정으로 정리해야 제품이 안 흔들림.

⚠ 사람 손(컨시어지)의 확장 한계

이미지·화이트글러브 설치는 사람 노동. 1차 베타엔 OK, 수요 검증 후 자동화/클라우드 전환 필수.

⚠ 결제 없으면 매출 0

기능 완성도와 무관하게 결제 경로부터 있어야 함. 가격 구조(C1) 먼저.
