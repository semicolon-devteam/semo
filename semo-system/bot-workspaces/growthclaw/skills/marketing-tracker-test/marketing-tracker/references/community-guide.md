# Community Guide — 커뮤니티별 특성 & 파싱 참고

## Naver Cafe
- **접근**: 데스크톱은 iframe 기반 → 모바일 URL(`m.cafe.naver.com`) 사용
- **비공개 카페**: 로그인 필요 → 파싱 실패 시 삭제로 오판하지 않기
- **삭제 마커**: "삭제된 게시글입니다", "존재하지 않는 게시글"
- **홍보 팁**: 신규 계정 바로 홍보 금지, 활동 이력 필요
- **삭제 패턴**: 관리자 모니터링 활발, 24시간 내 삭제 빈번

## FMKorea
- **접근**: Cloudflare 보호 있음 → 차단 가능성 높음
- **Best effort**: 차단 시 네트워크 에러로 분류, 삭제 아님
- **메트릭**: 조회수, 추천/비추천, 댓글
- **홍보 팁**: 유머/맥락 필수, 노골적 광고 즉삭
- **삭제 패턴**: 커뮤니티 신고 기반, 광고 감지 시 빠른 삭제

## DCInside
- **접근**: Cloudflare + 갤러리별 차이 큼
- **Best effort**: 모바일(`m.dcinside.com`) 시도, 실패 시 graceful
- **메트릭**: 조회수, 추천, 댓글
- **홍보 팁**: 갤러리 주제 매칭 필수
- **삭제 패턴**: 갤러리 매니저 재량, 주제 불일치 시 즉삭

## Clien
- **접근**: 비교적 단순한 HTML, 파싱 용이
- **메트릭**: 조회수, 공감, 댓글
- **홍보 팁**: 기술/IT 중심, 고품질 콘텐츠 선호
- **삭제 패턴**: 커뮤니티 신고 기반, 비교적 관대

## Reddit
- **접근**: `.json` 엔드포인트로 API 접근 (가장 안정적)
- **URL 변환**: `reddit.com/r/sub/comments/id` → `old.reddit.com/r/sub/comments/id.json`
- **메트릭**: upvotes, num_comments, view_count (가끔 null)
- **삭제 감지**: `removed_by_category` 필드 확인
- **홍보 팁**: 9:1 규칙 (자기 홍보 비율), 서브레딧 규칙 준수 필수
- **삭제 패턴**: 모더레이터 재량, AutoModerator 필터링

## 공통 주의사항
1. **네트워크 에러 ≠ 삭제**: 타임아웃, 차단, SSL 에러는 삭제가 아님
2. **Cloudflare 차단**: FMKorea/DCInside에서 흔함 → consecutive_errors로 추적
3. **3회 연속 실패**: 경고만, 자동 삭제 처리 안 함 → 수동 확인 유도
4. **파싱 실패**: HTML 구조 변경 가능 → 0으로 리포트하되 삭제 아님
