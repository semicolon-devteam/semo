## 🛠️ 기술 스펙

### 1. 번역 엔진
**Gemini 1.5 Flash-8B** (Google)
- **비용**: $0.04/1M input, $0.15/1M output
- **속도**: 지연시간 1초 내외
- **이유**: 최저가, SNS 게시물 번역에 충분

### 2. 백엔드 아키텍처
**Supabase Edge Functions** (Deno/TypeScript)
- **장점**: 기존 스택 통합, 빠른 구현
- **구조**:
  ```
  Client → Supabase Edge Function → Gemini API
              ↓
          Redis Cache (Upstash)
  ```

### 3. 캐싱 전략 (필수)
**Redis Cache-aside 패턴** (Upstash Serverless)
- **키 구조**: `translation:{post_id}:{source_lang}:{target_lang}`
- **TTL**: 7일
- **기대 효과**: 80~90% 비용 절감

```typescript
// 캐싱 플로우
async function getTranslation(postId, targetLang) {
  const cacheKey = `translation:${postId}:${targetLang}`;
  
  // 1. 캐시 확인
  const cached = await redis.get(cacheKey);
  if (cached) return cached;
  
  // 2. API 호출
  const translated = await gemini.translate(text, targetLang);
  
  // 3. 캐시 저장 (7일)
  await redis.set(cacheKey, translated, { ex: 604800 });
  
  return translated;
}
```

### 4. 온디바이스 번역 (보조)
**iOS**: Translation Framework (iOS 17.4+)  
**Android**: Google ML Kit

- **역할**: 서버 부하 경감 (개인 피드 탐색)
- **우선순위**: 온디바이스 → 실패 시 서버
- **제한**: 문맥 이해 낮음 (간단한 댓글만 추천)

### 5. Rate Limiting
- **사용자당**: 분당 10회, 일 300회
- **IP당**: 분당 30회
- **초과 시**: 429 응답 + "잠시 후 다시 시도" 메시지

## ⚠️ 리스크 관리

### 1. 번역 품질 저하 (신조어/슬랭)
**리스크**: "ㅋㅋㅋ", "알잘딱깔센" 같은 신조어 오역

**대응책**:
- **글로사리 API**: 스트리머별 용어 사전 구축
  - 예: "ㅋㅋㅋ" → "lol", "개추" → "I agree"
- **사용자 피드백**: "번역 신고하기" 버튼 (오역 수집)
- **Phase 2**: 커뮤니티 크라우드소싱으로 사전 업데이트

### 2. 비용 폭발 (봇 공격)
**리스크**: 악의적 사용자의 무한 번역 요청

**대응책**:
- **Rate Limiting**: 사용자당 일 300회
- **CAPTCHA**: 의심 행동 감지 시 발동
- **모니터링**: 일 $50 초과 시 알림

### 3. GDPR/CCPA 위반
**리스크**: 사용자 정보가 번역 API로 전송

**대응책**:
- **마스킹**: 사용자 ID, 위치 정보 제외 (텍스트만 전송)
- **DPA**: Google과 데이터 처리 계약 체결
- **약관**: "번역 시 텍스트가 Google API로 전송됨" 고지

### 4. API 장애
**리스크**: Gemini API 다운 → 번역 기능 중단

**대응책**:
- **폴백**: 온디바이스 번역 (품질 낮지만 가용성 유지)
- **에러 메시지**: "번역 서비스 일시 중단, 잠시 후 다시 시도"
- **Phase 2**: 멀티 프로바이더 (GPT-4o mini 폴백)
